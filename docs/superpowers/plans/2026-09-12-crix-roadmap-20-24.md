# CRIX roadmap #20–#24 implementation plan

**Goal:** complete the remaining advanced-risk research stack without changing `/api/v3` scoring semantics, then publish a fully validated release.

## Boundaries

- Research/offline-first. Existing `CRIX-MonoBoost@2.0.0` and `/api/v3` score semantics stay frozen during #20–#24.
- Every result carries horizon/assumption/model IDs; IFRS 9 and Basel outputs are explicitly research-style, not compliance claims.
- Prefer pure NumPy/Python and visible formulas. Do not add a solver or framework when sorting/enumeration/pure functions are enough.
- All stochastic work is deterministic for a master seed and bounded-memory/chunked.

## #20 — correlated portfolio loss

Create `model/portfolio_risk.py` and tests.

- Validate aligned PD/LGD/EAD and common horizon/currency metadata.
- One-factor Gaussian latent default model `sqrt(rho)Y + sqrt(1-rho)epsilon`.
- Counter/obligor-stable RNG so seeded output is invariant to chunk size.
- Stream scenario total losses; return EL, UL, VaR and ES at requested levels, independent baseline, marginal default rates, Monte Carlo standard error, histogram/quantiles.
- Withhold 99.9% metrics below 100k scenarios and state why.
- Tail contribution is scenario-conditioned exposure contribution and must reconcile to ES when requested.
- Tests: analytic independent mean/variance, rho=0, seed/chunk invariance, invalid rho/inputs, empty/single name, tail-resolution guard, contribution reconciliation.

## #21 — macro-conditioned stress

Create `model/macro_stress.py`, `model/macro_registry.json`, a small immutable public macro fixture/artifact, and tests.

- Start with US unemployment and effective/federal funds rate data only where traceable.
- Registry records source, series, frequency, geography, publication/vintage semantics, checksum and revision caveat.
- `asof_join_macro` uses publication-available dates and never reference-period future values.
- Interpretable logistic/hazard logit overlay with explicit coefficients, lags, standardisation and support range.
- Baseline/adverse/severe scenario paths are versioned and extrapolation is flagged.
- Propagate PD shocks into #20-compatible horizon inputs; do not claim causality.
- Tests: unpublished-value leakage fixture, unit/frequency validation, support/extrapolation, scenario identity/order where the configured path is strictly adverse.

## #22 — IFRS 9-style ECL research

Create `model/ifrs9.py` and tests.

- Pure cumulative-to-marginal PD conversion with monotonic/bounds checks.
- Stage policy object: Stage 1 12m, Stage 2 lifetime after SICR/DPD backstop, Stage 3 default/credit-impaired; configurable cure/probation.
- ECL = sum(marginal PD × LGD × EAD × discount factor), scenario weighted with nonnegative weights summing to 1.
- Stage 1 uses default events in next 12 months; loss amounts remain aligned to those intervals under the declared convention.
- Tests use hand-calculated loans, SICR/DPD/default/cure fixtures, discounting, invalid weights and insufficient curves.

## #23 — capital research

Create `model/capital.py` and tests.

- Separate expected loss, unexpected loss, simulation tail economic capital and regulatory-inspired analytic capital.
- Implement a small visible IRB-style corporate formula under an explicitly versioned research assumption set; validate PD/LGD/EAD/maturity domains and cap correlation formula exactly to its declared version.
- RWA-style conversion uses explicit capital ratio; no jurisdiction/universal-compliance claim.
- Economic capital = selected VaR/ES measure minus EL, floored/labelled by convention.
- Tests: independent toy formula fixtures, zero EAD, invalid LGD for analytic formula, monotone sensitivity where guaranteed, contribution reconciliation.

## #24 — challenger governance and optimisation

Create `model/decisioning.py` and tests.

- Challenger comparison consumes cached same-cohort predictions/metrics and compatibility metadata; promotion gates calibration/stability/OOT before AUC.
- Promotion rule can reject a higher-AUC challenger.
- Direct sorted optimiser for the single budget/EL frontier case where provably correct.
- Exact bounded enumeration for small coupled binary portfolios (research/reference solver), with deterministic tie-break and explicit candidate ceiling; no fake polynomial claim.
- Constraints: budget, EL amount/rate, approval count, segment concentration, policy eligibility. Tail risk is independently re-evaluated through #20 after candidate selection when configured.
- Return selected IDs, rejected reasons, binding constraints, status `optimal`/`infeasible`, and objective value.
- Tests compare exact optimiser to exhaustive toy optimum, sorted frontier to direct solution, infeasibility, eligibility, concentration and EL reconciliation.

## Integration/reporting

Create `model/advanced_risk_report.py`/`model/ADVANCED_RISK_REPORT.md` only from public/synthetic aggregate inputs; add the advanced test suite to the existing Python governance CI. Model-validation workflow remains responsible for heavyweight source-backed training from #14–#19; #20–#24 pure engines are covered by fast deterministic tests plus an offline research report/benchmark.

## Final release sequence

1. Open PR for #20–#24 after implementation tests pass.
2. Require Node verify/benchmark + Python governance + model validation green.
3. Merge and close #20–#24.
4. Update README, CHANGELOG and relevant Markdown/model-card docs against the merged implementation.
5. Inspect existing tags/releases and choose the next semantic version from repository history rather than guessing.
6. Update package/runtime/version message consistently; rerun final CI green on the release PR.
7. Merge, tag the exact green main SHA, publish release title/notes with research disclaimers.
8. Verify Render deployment is on that SHA/version and the live root/version message reports the new release.
